                          FEATURE OVERVIEW
================================================================================

Feature 1: PROPOSAL CACHING
─────────────────────────────

Problem:
  • Users run similar projects → agents re-generate similar proposals
  • No way to rate effectiveness over time
  • Lost knowledge from previous runs

Solution:
  • Cache proposals with unique keys
  • Track success: which proposals were selected, how well they worked
  • Find & reuse high-quality proposals from cache
  • TTL-based eviction (keep cache fresh)

Key Functions:
  proposalCache.set(proposal, key)              → Store
  proposalCache.get(key)                         → Retrieve
  proposalCache.findSimilar(keywords)            → Search
  proposalCache.recordEvaluation(key, outcome)   → Log results
  proposalCache.getSuccessScore(key)             → Get weighted score
  findReuseableProposal(prompt, agent, phase)    → Smart recommendation

Cost Savings:
  • Cache hit: Skip API call ($0.01-0.05 saved per hit)
  • With 30% hit rate: Save ~$0.20 per run (over 1000 runs: $200)

Memory:
  • ~1KB per cached proposal
  • 1000 proposals = ~1MB
  • Max 1000 proposals (configurable)


Feature 2: CUSTOM SCORING RUBRICS
──────────────────────────────────

Problem:
  • Default scoring doesn't fit all domains
  • Users can't define what "good" means for their project
  • One-size-fits-all rubric misses domain-specific priorities

Solution:
  • Define scoring dimensions (e.g., alignment, technical, ethics)
  • Assign weights (what matters most?)
  • Score proposals against rubric
  • Rank by overall score
  • Or generate custom rubric from natural language description

Default Rubrics:
  Software Engineering (alignment 25%, technical 30%, ethics 20%, novelty 10%, coherence 15%)
  Scientific Rigor (methodology 35%, reproducibility 25%, impact 20%, ethics 20%)

Key Functions:
  getRubricForProject(type)                      → Load default
  generateCustomRubric(description, type)        → Create from prompt
  scoreProposalWithRubric(proposal, rubric)      → Score single
  rankProposalsWithRubric(proposals, rubric)     → Score & rank
  saveRubric(), loadAllRubrics()                 → Persistence

Cost Impact:
  • Per-proposal: 1-2 Gemini Flash calls (~$0.001-0.002)
  • 3 proposals: 6 calls (~$0.01 total)
  • Negligible compared to agent calls

Quality Impact:
  • Better alignment with user expectations
  • Reduced manual review time
  • Consistent scoring across runs


Feature 3: MULTI-MODEL SYNTHESIS
─────────────────────────────────

Problem:
  • Single model has limitations
  • No leverage of multiple AI providers
  • Can't optimize for cost vs. quality tradeoff

Solution:
  • Call multiple models in parallel
  • Each model proposes synthesis approach
  • Use ensemble voting to merge results
  • Track consensus & disagreements
  • Support cost-optimized, balanced, and quality modes

Available Models:
  Google Gemini 3 Pro          - $0.075/1k input, $0.3/1k output   (fast, balanced)
  OpenAI GPT-4o               - $5/1k, $15/1k                      (reasoning)
  Anthropic Claude 3.5 Sonnet  - $3/1k, $15/1k                      (nuanced)
  Groq Mixtral 8x7b           - $0.00024/1k, $0.00024/1k           (very fast)
  Mistral Mistral Large       - $0.0048/1k, $0.014/1k              (balance)
  Perplexity Sonar Pro        - $5/1k, $15/1k                      (creative)

Key Functions:
  selectOptimalModels(budget, roles)             → Pick best models
  synthesizeProposalsMultiModel(proposals)       → Full synthesis
  synthesizeCheap(proposals, budget)             → Budget-constrained
  synthesizeBalanced(proposals, budget)          → Cost-quality balance
  synthesizeQuality(proposals)                   → Highest quality

Cost Scenarios (3 proposals):
  Cheap (Groq + Mistral):     ~$0.012 ✅
  Balanced (Gemini + Claude): ~$0.18  ✅
  Quality (Claude + GPT-4):   ~$0.45  (expensive)

Quality Impact:
  • Consensus score >0.75 → models agree (good synthesis)
  • Identify disagreements → highlights risks
  • Ensemble effect: Better than any single model

Try cache first:
  const cached = await findReuseableProposal(prompt, agentId, phase, projectType);

  }

  const rubric = getRubricForProject('software');
  const ranked = await rankProposalsWithRubric(proposals, rubric, prompt);

  const result = await synthesizeBalanced(proposals, prompt, costBudgetUSD);
